# 生产环境内容安全密钥配置核对清单

> 目的：确认线上已关闭"开发期放行(dev-bypass)"，内容安全接口真实生效。
> 注意：本清单不含任何真实密钥值，仅用于核对步骤。

---

## 背景

`server/src/services/security.js` 中 `msgSecCheck` / `imgSecCheck` 在未配置
`WX_APPSECRET` 时会走 `dev-bypass` 降级放行（仅打印警告、不拦截）。
若生产 `.env` 未填真实密钥，违规昵称将**不被拦截**——这是本次被警告的潜在根因。

因此申诉前必须确认：生产服务器 `server/.env` 的 `WX_APPID` 与 `WX_APPSECRET`
均为**真实有效值**。

---

## 核对步骤（在生产服务器执行）

1. 登录生产服务器（Ubuntu）：`ssh root@47.93.96.20`
2. 进入服务端目录：`cd /opt/liuer/server` （或实际部署目录）
3. 确认 `.env` 存在且含真实密钥：
   ```
   grep -E '^WX_APP(ID|SECRET)=' .env
   ```
   - `WX_APPID=` 应为小游戏真实 AppID（非占位符）
   - `WX_APPSECRET=` 应为真实密钥（非 `your_wx_appsecret`、非空）
4. 快速自检接口是否真实生效（不泄露密钥值，仅打印是否配置）：
   ```
   node -e "require('dotenv').config(); const s=process.env.WX_APPSECRET||''; console.log('WX_APPSECRET 已配置:', (s && s!=='your_wx_appsecret')?'是':'否');"
   ```
5. 运行内容安全自检脚本，截图真实接口返回作为证据：
   ```
   node scripts/test_sec_check.js
   ```
   预期：配置了真实密钥时，`msgSecCheck` 返回 `{"ok":true,"errcode":0,...}`
   （正常昵称）或 `{"risky":true,"errcode":87014}`（违规内容）。

---

## 若未配置 / 仍为占位符，请按以下修复

编辑 `server/.env`：
```
WX_APPID=<小游戏真实AppID>
WX_APPSECRET=<微信公众平台获取的真实密钥>
```
获取路径：微信公众平台 → 开发 → 开发设置 → AppSecret（需管理员扫码）。
修改后重启服务：`pm2 restart liuer` 或 `npm start`。

---

## 验证上线已拦截（可选）

查看服务端日志，确认不再出现 `[Security] 未配置 WX_APPSECRET，跳过 msgSecCheck` 警告：
```
journalctl -u liuer -n 200 | grep Security
```
